# Project Website

This folder contains a local, multi-page project website built from the supplied Word document. It uses HTML, CSS and vanilla JavaScript. It does not need a server, build step, framework or internet connection to open locally.

## Open the website on your computer

1. Extract the `project-website` folder from the ZIP file.
2. Keep the folder structure together.
3. Double-click `index.html` to open the Executive Overview in your browser.
4. Use the left navigation to move between pages. On a phone, use the menu button.

The site's CSS, JavaScript, font placeholder and document images are stored in the `assets` folder. The website makes no external requests when opened locally. The document's original hyperlinks remain clickable; opening one of those links will visit that external website.

## Uploading the folder to GitHub

1. Create a GitHub repository.
2. Choose **Private** when creating the repository if the document must remain private.
3. Upload the contents of this `project-website` folder, keeping the folders and filenames unchanged.
4. Do not enable GitHub Pages for a private document.

**Privacy warning:** A GitHub Pages site is public on the internet even when the repository is private. A free GitHub account cannot use Pages with a private repository. To keep the document private, keep the repository private and do **not** turn on Pages. Open `index.html` from the folder on your computer, or share the ZIP directly instead. Remove personal details from the document first if you intend to publish a public website.

## Where to make changes

- **Numbers and lists:** `assets/js/project-data.js` is the single source of truth for extracted project data. Calculated values are generated by JavaScript.
- **Colours and layout:** the `:root` section near the top of `assets/css/style.css` contains the colour variables. Shared layout and components are in the same stylesheet.
- **Optional font:** place the local font file at `assets/fonts/Manrope.woff2`. The site uses a system-font fallback until that file is added.
- **Document blocks:** each document block is inside its page's HTML and marked by `<!-- DOCUMENT CONTENT START -->` and `<!-- DOCUMENT CONTENT END -->` comments. The complete original document is on `detailed-documentation.html`.
- **Images:** extracted Word images are in `assets/images/`.
- **Shared interactions and charts:** `assets/js/app.js` and `assets/js/charts.js`.
- **What-if tools:** `assets/js/whatif.js`, mounted on `index.html`.

## Verification summary

- Ten HTML pages are included, with the same ten static sidebar links in the required order on every page.
- The detailed-documentation page contains the complete converted document. Section document blocks are sliced from the same conversion, so their source text is consistent by construction.
- The About Us page reuses the title-page content with the student number omitted, as requested.
- The References page contains the reference-list block from the original document.
- Source document counts checked: 50 headings, 5 tables, 2 images, 66 hyperlink elements, 27 list items and 17 reference entries.
- Financial checks: the eleven budget accounts total the documented delivery baseline; the baseline plus reserve equals the funding ceiling; the three ROI scenarios are checked against the document's stated figures.
- All local HTML resource paths and page-to-page navigation links are checked. The pages include `noindex, nofollow, noarchive` and `no-referrer` metadata.
- The website code does not load remote scripts, stylesheets, fonts, images, analytics, maps or embeds. External links inside the document are the only external URLs retained.

No claim of browser screenshot testing is made; the local headless browser could not start in the build environment. The files were checked by parsing the HTML, validating JavaScript syntax, checking local paths and comparing extracted document text.
